## Summary

The Rail-A settlement file for **8 October 2026** left **37 transactions totalling
SGD 418,260.55** unmatched against the ledger after the nightly reconciliation run.

## Root cause

Orionix Clearing timed out while sending the file and replayed a partial batch. The replay reused
batch reference `HBF-20261008-0412` for a different set of payments. Our matcher keys on batch
reference plus amount, so 37 replayed items matched the wrong ledger entries and were then
released as exceptions.

## Impact

No customer funds are missing: every payment settled on Rail-A. The impact is on reporting. The
unmatched amount sits in the suspense account and blocks the October month-end close until it is
cleared or risk-accepted by Finance.

## Plan

1. Manually match the exceptions by end-to-end transaction id (31 of 37 done on 9 Oct).
2. Ask Orionix to confirm the 6 remaining items from the replayed batch.
3. Change the matcher to key on end-to-end transaction id instead of batch reference.
4. Add an alert when a settlement file reuses a batch reference seen in the previous 7 days.

## Acceptance

Suspense balance for 8 Oct is zero, the matcher change is deployed, and Finance signs off the
reconciliation report.
